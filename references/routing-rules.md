# 路由规则：阶段一（建库）/ 阶段二（学习）

## §1 意图识别 prompt（skill 内嵌）

```
你是「榨书成师」Skill 的路由器。基于用户输入，判断走哪个阶段：

阶段一 建库 —— 用户上传电子档 / 指定目录，要「整理 / 处理 / 转成知识库 / 识别 / 校对」
   例："把 /books/机器学习 里的书整理成知识库"、"这几本 PDF 帮我处理一下"、"扫描件帮我识别成文字"
阶段二 学习 —— 用户要「开始学 / 教我 / 继续上次 / 考考我」
   例："开始教我机器学习"、"继续上次的学习"、"从零开始教我线性代数"

判断要点：
- 给文件/目录 + 「整理/处理/识别/建库」→ 阶段一
- 「开始学/教我/继续/考我」→ 阶段二
- 同一条消息含两阶段（如「建库然后教我」）→ 先阶段一，完成后再自动进入阶段二
- 「教我 X」但没有给书 / 目录 / 已建 md → 先做 §2 书源校验，再决定
- 与学习无关 → 短答 + 一句引导（"给我一批书或一个目录，我帮你建成知识库，再教你"）

内部使用，不要输出给用户：
{"stage": "build" | "learn"}
```

## §2 书源校验（无书可依分支）

用户说「教我 X」但**没给书、没有目录、也没有已建的 md**时，不要空转、也不要硬撑「书籍未涉及，以下为补充」（那是对书里漏掉某个点设计的，不是对整门课没书设计的）。一句话给出两条路，让用户选：

1. 「给我一批书或一个目录，我帮你建成知识库再教」；
2. 「先按通用教材体系讲，但**所有内容都会标注『非出自你的书』**，仅作补充讲解」。

- 若用户选 2，标注必须**每节都出现**，不能只在开头出现一次；并明确告知「这不是榨书成师的正规用法，内容未经你的书核对」。

## §3 阶段一：建库

按 @references/kb-building-rules.md 执行。要点：

1. 输入侧校验与告知：确认用户对书源有合法使用权（拒绝盗版 / 无权书源）；扫描件 / 图片若走模型读图识别，先告知「将发送给模型」并征得同意（见 @references/compliance-rules.md §0）。
2. 确定「领域名」：用户给目录则用目录名（或让用户确认领域名）；上传文件则问一次领域名（不猜）。
3. 递归扫描目录所有文档，去重、按文件名排序。
4. 逐个转换 + 校对 + 落盘 + 建索引（扫描 PDF 走 render → OCR 链路，见 @references/kb-building-rules.md §1；规模大用 `--dir` + manifest 断点，见 @references/kb-building-rules.md §5）。
5. 完成后报告：处理了 N 个文档、产出 M 个 Markdown、索引含 K 个知识点，并问「要现在开始学吗」。

## §4 阶段二：学习

按 @references/socratic-rules.md 执行。要点：

1. 确定领域：用户说「继续」则读 `<workspace>/.socratic-tutor/` 下已有领域；多领域则让用户选。
2. 读 `progress.md` 定位当前位置。
3. 逐知识点问答，直到用户退出或全部学完。
4. 用户中途退出 → 更新 `progress.md` 当前位置，明说「已记录，下次从这继续」。

## §5 名称规范化

- 领域名统一小写英文或用户原词，作为目录名：`<workspace>/.socratic-tutor/<领域>/`。
- 文档格式按扩展名识别：`.pdf`（文本层/扫描）、`.png/.jpg/.jpeg/.webp`（图片）、`.docx`、`.epub`、`.html/.htm`、`.txt/.md`。
